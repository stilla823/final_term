Between the Lines

Type a short dialogue scene. Get a three-shot storyboard with camera position, character placement and an acting note for each shot.

Design Spec, version 1. Final Term Project, due 16 Nov 2026. Your Name, Student ID

The saved demo result for the sample scene. Panels are drawn in code from original composition templates.

1The idea

Between the Lines helps film students and beginner filmmakers turn a short dialogue scene into a three-shot storyboard. The user types the dialogue for one or two characters and can add the location and what the audience should feel or understand. The app returns three storyboard panels, each with its shot size, camera position, character placement, visible action and one acting note, plus one optional action or line to add before the scene and one after, kept apart from the original script. It matters because beginners often know what a scene says but not how to show it. Seeing the scene broken into three concrete shots, each with a reason tied to the directing intention, gives them something specific to discuss, test and change, whether they are planning a new scene or looking for a different way to direct one they have already written.

AI 연출 제안

장면 시작 전: …

장면 끝난 후: …

  1. Mode labelAlways visible. Says whether the app is in demo mode or live AI mode.
  2. Character countChoose 1 or 2. Decides which speakers are allowed (A only, or A and B).
  3. Dialogue fieldOne line per turn, written A: 대사 or B: 대사. Checked before anything is generated.
  4. Location (optional)Where the scene takes place. If it is empty, the model states its own assumption.
  5. Directing intention (optional)What the audience should feel or understand. The reason on each shot refers back to it.
  6. Load sampleFills the whole form with the sample scene.
  7. Make storyboardChecks the dialogue, then shows the saved result (demo) or generates one (live).
  8. Shot card, three timesPanel, shot size, camera position, placement and action, dialogue, acting note, reason.
  9. AI 연출 제안One optional suggestion before and one after the scene, each with what it changes. Never merged into the script or the shots.

Result card, in detail

Each of the three cards has the same seven parts, so a student can compare shots at a glance.

PartWhat it showsWhy it is there
PanelWhat the camera sees, drawn as silhouettes labeled A and BFrame size and placement are visible before reading any text. The close-up shows B much larger than the wide shot.
Shot sizeMedium two-shot, close-up, wide shotTeaches the vocabulary.
Camera positionWhere the camera stands relative to the characters or the placeThe student can reproduce the shot.
Placement and actionWhere each character is and what is visibleBlocking for the shot.
DialogueThe user's own lines for this shot, or 대사 없음Shows which lines each shot covers. The model cannot rewrite them.
Acting noteOne thing an actor can perform, such as a pause or a look away on a given wordMoves from camera to performance.
ReasonOne short sentence on how the shot supports the directing intentionThe student learns why, not only what.

4User flow

  1. The user opens the app. It starts in demo mode.
  2. The user presses 예시 불러오기, or chooses 1 or 2 characters and types a scene.
  3. The user presses 스토리보드 만들기.
  4. The app checks the dialogue. If a line is wrong, it names the line and the rule, and the user fixes it and presses the button again.
  5. The app shows three shot cards and, below them, AI 연출 제안.
  6. The user edits the scene and repeats from step 3.

Error and edge cases

The required error case is the speaker outside the cast. The others are the cases most likely to confuse a user, so each one has a message that says what happened and what to do next.

Speaker outside the cast (main error case)

Input: 2 characters selected, line 2 is “C: 안녕”.

2번째 줄의 화자 C는 선택한 인원에 없습니다. 2명 장면에서는 A와 B만 쓸 수 있어요.

Nothing is generated. The user fixes the line or changes the character count.

Empty dialogue, or a line without a speaker label

Input: empty field, or line 3 reads “다음에 보자”.

대사를 입력해 주세요. 한 줄에 한 마디씩 “A: 대사” 형식으로 적습니다.
3번째 줄에 화자 표시가 없습니다. “A: 대사” 또는 “B: 대사” 형식으로 써 주세요.

One message per case. A two-character scene where B never speaks is valid.

Edited scene in demo mode

Input: the user changes any part of the sample and presses the button.

직접 고친 장면은 라이브 AI 모드에서만 만들 수 있습니다. 데모 모드에서는 저장된 예시만 보여 드려요.

Button: 예시 다시 불러오기. The saved storyboard is never shown as if it were generated for the edited input.

Live mode unavailable, or model output fails the check

Input: no local model is running, or the reply has the wrong number of shots, an unknown ID or missing dialogue lines.

라이브 AI 모드에 연결할 수 없습니다. 모델 주소와 이름 설정을 확인하거나 예시 데모를 불러오세요.
스토리보드를 만들지 못했습니다. 모델 응답이 형식에 맞지 않았어요.

Buttons: 다시 시도 and 예시 불러오기.

6AI and prompts

ModeModelHow it is set up
Demo (default)NoneShows the saved result for the unchanged sample scene. No key, download or paid service.
LiveA locally running open-source instruction model, not yet chosenBehind a separate adapter (model_adapter.py). The endpoint and model name are read from settings outside the source code, for example LLM_ENDPOINT and LLM_MODEL.

How the model will be chosen. The license allows free use, it runs on an ordinary laptop, it follows a JSON format reliably, and it writes acceptable Korean. The choice and its license will be written into this page and the README. The adapter can also be pointed at another model, including Claude, without changing the rest of the app.

Key prompt 1: instructions (system message)

Turn the input scene into exactly three filmable shots. Use only the characters
provided. Preserve the original dialogue and its order by referencing the
supplied dialogue line IDs. Choose a composition template from the supplied
catalog for each shot. For every shot, return the template ID, character
placement, camera position, visible action, acting note, and a brief reason for
the directing choice. Ground the choices in the directing intention when one is
provided. If you assume a location or an emotional interpretation, state the
assumption. Return optional before-scene and after-scene suggestions in separate
fields. Return structured JSON.

Key prompt 2: scene (user message, filled in by the app)

Characters: A, B
Location: 복도 출입문 앞
Directing intention: B는 같이 가고 싶지만 붙잡지 못한다.
Dialogue lines:
L1 A: 너도 같이 갈래?
L2 B: 괜찮아. 먼저 가.
Composition templates:
medium_two_shot (A and B), ots_close_up (subject + foreground),
wide_empty_space (one or two characters), single_medium (one character)
Write every descriptive field in Korean.

Expected reply (abridged)

    "after":  { "kind": "dialogue", "text": "…", "effect": "…" }

}

Check before anything is shown

  • There are exactly three shots.
  • Every template ID is in the catalog and every character is one the user provided.
  • The dialogue line IDs, read across the three shots, include every original line exactly once and in the original order.
  • The dialogue text on screen comes from the user's input, looked up by ID. The model never supplies it, so it cannot rewrite it.
  • If any check fails, the app says the storyboard could not be generated and offers to retry or load the demo.

7System structure

Four parts, built only from free and open tools. Demo mode uses the first two layers and the renderer. Live mode adds the dashed box.

Interface: app.py (Streamlit)

Input form, mode label, dialogue check, error messages, three shot cards and the suggestions section.

↓

Demo mode: data/demo.json

The saved sample scene and its saved result. Shown only while the input matches the sample.

Live mode: model_adapter.py

Builds the prompt, calls a local open-source model, parses the JSON and runs the checks from section 6. Scaffolded first, so live mode is the part that may remain planned.

↓

Renderer: storyboard.py and data/templates.json

Draws each panel as SVG from the chosen template. The same code serves demo and live results.

8Risks and limits

What could go wrongHow the design responds
The model rewrites, reorders or drops dialogueIt returns line IDs only. The app prints the user's own text by ID and checks that every line is used once, in order.
The reply is malformed: wrong shot count, unknown template or characterThe reply is validated. On failure the user sees a clear message and can retry or load the demo.
The saved demo is mistaken for a real resultIt appears only for the unchanged sample, labeled 데모 모드 · 저장된 예시 결과. An edited scene gets a message instead.
The model reads too much into the emotionAssumptions are stated, each reason is tied to the directing intention, and the suggestions are optional and separate from the script.
A small local model gives generic or awkward KoreanKorean quality is a selection criterion. The user can retry, and the demo always works.
Live mode is not available on the user's computerA clear message and a button to load the sample demo.
A user's unpublished scene is exposedNothing is stored. In live mode the text goes only to a model on the same computer.

What the app will not do

  • Write, change or "improve" the user's dialogue.
  • Handle more than two characters, or produce a number of shots other than three.
  • Produce realistic images. Panels are schematic silhouettes that show framing and placement only.
  • Claim that its choices are the correct way to direct the scene. They are one option to react to.
  • Insert its suggestions into the script or the storyboard automatically.
  • Save scenes or require an account.
